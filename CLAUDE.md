# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Telegram-бот (aiogram 3, polling) на Python: пользователь кидает фото — бот
накладывает случайную фразу из `phrases.txt` в мемном стиле (Pillow). Плюс
предложка мемов в канал с ручной модерацией админом.

Тестов, линтера и CI в проекте нет — проверка изменений ручная (запустить бота
или дёрнуть функцию рендера напрямую).

## Команды

```bash
# окружение
python3 -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt

# запуск бота (обязателен только BOT_TOKEN)
export BOT_TOKEN="..."      # токен от @BotFather
export ADMIN_ID="123456"    # кому приходят заявки предложки; без него модерации нет
export CHANNEL_ID="@channel"  # куда постятся одобренные заявки И на что проверяется подписка
python bot.py

# docker
docker build -t memebot . && docker run -e BOT_TOKEN=... -e ADMIN_ID=... -e CHANNEL_ID=... memebot

# перегенерировать комбинаторные фразы -> generated_phrases.txt (phrases.txt НЕ трогает)
python generate.py

# выгрузить фото из канала (нужен telethon, его нет в requirements.txt)
pip install telethon && python scrape.py
```

Быстрая проверка рендера без Telegram:

```bash
python -c "from memegen import make_meme; open('out.jpg','wb').write(make_meme(open('in.jpg','rb').read(),'верх','низ').read())"
```

## Архитектура

Поток: `bot.py` (хендлеры/FSM) → `phrasebank.get_random_phrase` + `parse_phrase`
→ `memegen.make_meme` → фото обратно в чат. Всё остальное — сбоку.

- **bot.py** — единственная точка входа. Два middleware поверх всех апдейтов:
  `StatsMiddleware` (только сообщения → `stats.track`) и
  `SubscriptionGateMiddleware` (сообщения + колбэки), который блокирует **любое**
  действие для неподписанных на `CHANNEL_ID`. Гейт отключается сам, если
  `CHANNEL_ID` пустой, и всегда пропускает колбэк `check_sub` — иначе подписку
  нельзя подтвердить. Ошибка `get_chat_member` трактуется как «не подписан».
- **phrasebank.py** — база фраз + «колода»: на каждый чат в `state.json` лежит
  перемешанный список индексов, из которого фразы вынимаются без повторов.
  База склеивается из двух файлов: `phrases.txt` (кураторская, лежит в git,
  можно перезаливать целиком) и `phrases_user.txt` (одобренные админом
  пользовательские фразы, лежит в `DATA_DIR`) — разделение как раз чтобы
  перезаливка общей базы не сносила пользовательские. Оба перечитываются на
  каждый запрос, поэтому пополнение работает без рестарта; при изменении
  количества строк колода пересобирается (счётчик `total`). Формат строки —
  `верх|низ` либо одна строка (уходит вниз); ведущий `~` помечает фразу как
  «только демотиватор» (см. memegen.py); `#` и пустые строки игнорируются.
- **memegen.py** — `make_meme` сама решает стиль: демотиватор (чёрное поле,
  рамка, PT Serif Italic) с вероятностью `DEMOTIVATOR_CHANCE` (0.2), **всегда**
  если фраза начинается с `~` (`DEMOTIVATOR_ONLY_PREFIX` — пометка «формы
  верх/низ у неё нет») или если она без `|` и длиннее
  `VERY_LONG_UNSPLIT_CHARS` (110); иначе классика Impact-стиля. Фразу без `|`
  длиннее `LONG_PHRASE_CHARS` (50) классика всегда режет на верх/низ
  (`_split_phrase_for_layout`: сначала запятая ближе к середине, иначе баланс по
  символам + ближайший союз, и верхняя строка не обрывается на предлоге).
  Остальной рандом: шрифт из `FONT_CHOICES` (только жирные капсы — рукописные
  выпилены, с обводкой нечитаемы) + размер ±12% + толщина обводки, отступы от
  краёв. Если блок текста не влезает в 32% высоты — шрифт ужимается в цикле.
- **submission_queue.py / phrase_queue.py / stats.py** — три плоских JSON-файла
  (`submissions.json` — мемы в предложке, `phrase_submissions.json` — фразы на
  модерации, `stats.json` — активные чаты по месяцам), read-modify-write на
  каждый вызов, без блокировок. Это ок только потому, что бот — один
  polling-процесс. Обе очереди устроены одинаково: `add_submission` выдаёт
  инкрементный строковый id, статус `pending` → `approved`/`rejected`, у заявки
  хранится `admin_message_id`, чтобы править сообщение у админа. Все файлы
  состояния в `.gitignore` и создаются сами, см. раздел «Деплой».
- **generate.py** — офлайн-скрипт, в рантайме бота не участвует. Комбинаторный
  генератор с `random.seed(7)`; ключевая инвариант — у каждого шаблона свой
  `cap` в `SIMPLE_TEMPLATES`/`GEN_ENTRIES`, иначе один шаблон заполняет треть
  базы. Часть фраз согласуется по роду через `states` (кортежи `(слово, род)`) и
  `VERB_ENDINGS`, поэтому новые слова в `states` добавлять **с родом**.
  Результат пишется в `generated_phrases.txt` — переносить в `phrases.txt` руками.
- **chatgen.py** — второй рендерер, не связанный с memegen: рисует с нуля
  скриншот переписки в iOS-телеграме (обои, пузыри с хвостиками, реакции,
  ответы, пересылки, фото, голосовые, кружки, стикеры, файлы, звонки, шапка,
  статусбар, поле ввода). Все константы — в «пойнтах» айфона, `PX()` переводит
  их в пиксели; метрики (кегль 17.6, строка 23, паддинги 10/5, радиус 14,
  хвост 5.7x8, поля 10) **сняты пипеткой с реального скриншота**, а не
  подобраны на глаз — менять их «на глазок» не стоит. Темы лежат в `THEMES`.
  Тем шесть (`THEMES`): две тёмные и четыре светлые, у светлых общая основа
  `_LIGHT` — различается только фон. Всё, что раньше было захардкожено белым
  полупрозрачным (подложка цитаты, чип реакции, волна голосового, круг медиа),
  вынесено в поля темы — иначе на светлом фоне это просто исчезало.
  Галочки прочтения (`_tick`) — отдельная история: вторая галочка рисуется
  ОДНОЙ чертой, её короткий хвостик у Apple спрятан под длинной чертой первой.
  Если рисовать обе целиком, получается «W». Рисуются с запасом по размеру и
  уменьшаются, иначе тонкие диагонали идут лесенкой. Время и галочки прижаты
  к базовой линии текста (коэффициент 0.536 от кегля), а не к его середине.
  Две ловушки: `ImageDraw` не смешивает альфу, а замещает её, поэтому всё
  полупрозрачное рисуется на отдельном слое через `overlay()`; и Pillow
  ругается на `rounded_rectangle` с `corners=`, если радиус больше половины
  стороны — в `bubble_mask` он поэтому клампится.
- **Длинная переписка сама раскладывается на несколько экранов**
  (`make_chat_pages` в chatgen). Она НЕ режется на куски: вместо этого по всей
  высоте расставляется несколько окон во весь экран, первое упирается в начало
  переписки, последнее в конец, смещение задаётся параметром `scroll`. Так
  каждый скрин заполнен целиком, а нахлёст между соседними ровный и небольшой.
  Нарезка кусками (как было сначала) давала либо пустую стену обоев на коротком
  экране, либо половину сообщений продублированной — обе версии сразу выдавали
  подделку. Больше десяти экранов не отдаём: столько влезает в альбом.
- **chatflow.py** — сценарий «Переписка» поверх chatgen, отдельным роутером
  (`dp.include_router` в конце `bot.py`). Мастер спрашивает имена, аватарки,
  тему, время и шаг, дальше включается конструктор: обычный текст сразу
  становится репликой, присланное фото — картинкой, кнопки нужны только для
  голосовых, кружков, стикеров, файлов, звонков, реакций и дат. Черновик
  живёт в FSM, картинки хранятся как `file_id` и скачиваются только при
  отрисовке. `CANCEL_TEXT` обязан совпадать с `BTN_CANCEL` в `bot.py` —
  выход из сценария обрабатывает общий хендлер отмены.
- **Эмодзи.** Порядок источников: `fonts/emoji_apple/` (выгрузка из системного
  шрифта Apple скриптом `tools/export_apple_emoji.py`, 1925 PNG) → PNG 512px
  из noto-emoji, качаются по сети в кэш → битмап из `NotoColorEmoji.ttf`.
  Напрямую эппловский шрифт подключить нельзя: в бинарных сборках Pillow нет
  Raqm, без неё не собираются флаги и клавиши, а разбор таблицы `sbix` тянет
  в память 74 МБ при 256 МБ на хостинге. Поиск идёт по именам глифов
  (`u1F601`, `u0031_u20E3`, `u1F468_u1F4BB.0`, суффиксы `.M`/`.W`); варианты
  тона кожи не выгружены — подставляется жёлтый. Семьи и пары Apple собирает
  из половинок глифов, их достать нельзя — для них остаётся откат на Noto.
  Разбор строки на эмодзи идёт кластерами по UTS#51: рвать 👨‍💻 или 🇷🇺 нельзя.
- **stickers.py** — личные стикерпаки, отдельный роутер. Кнопка «в стикеры»
  вешается ПОД самой картинкой, и колбэк берёт `file_id` из
  `callback.message.photo` — поэтому, в отличие от остальных кнопок бота, она
  переживает перезапуск и не зависит от FSM. Три требования телеграма, из
  которых растёт вся логика: у пака два имени (`name` для ссылки — латиница,
  начинается с буквы, без двойных подчёркиваний, обязан кончаться на
  `_by_<юзернейм бота>`; `title` — любой текст, его и вводит юзер, а `name`
  генерится транслитом со случайным хвостом от коллизий); стикер обязан быть
  WEBP/PNG со стороной 512 и весом до 512 КБ, так что `file_id` мема не
  переслать — картинка скачивается и пережимается; каждому стикеру нужен
  эмодзи (ставим дефолтный, сразу предлагая сменить через
  `set_sticker_emoji_list`, для чего пак перечитывается ради `file_id`
  последнего стикера). Потолок — 120 стикеров на пак. Список паков лежит в
  `sticker_packs.json` в `DATA_DIR`.
- **scrape.py** — отдельная утилита на Telethon с захардкоженными
  API_ID/API_HASH и именем канала; к боту отношения не имеет.

## Деплой

Бот живёт на **[bothost.ru](https://bothost.ru/)** — российский PaaS-хостинг под
ботов (Telegram/Discord/VK и др.), рантаймы Python/Node/Go/Java/PHP плюс
кастомный Dockerfile. Деплой из GitHub/GitLab: пуш в выбранную ветку → сборка и
перезапуск; главный файл (`bot.py`) и переменные окружения задаются в панели.
Тарифы: Starter бесплатно (1 бот, 1 vCPU, 256 MB RAM, 0.5 GB SSD), Basic 99 ₽/мес,
Pro 250 ₽/мес; на платных — Volume, бэкапы. Логи в реальном времени на всех.

**Главное следствие для кода:** между деплоями переживает только папка
`/app/data`, всё остальное перезаписывается кодом из репозитория. Поэтому пути
к файлам состояния идут через `storage.data_path()`: каталог берётся из
переменной `DATA_DIR`, а без неё — каталог с кодом, как раньше (локальный
запуск не меняется). На хостинге должно быть выставлено `DATA_DIR=/app/data`,
иначе `state.json`, `stats.json` и `submissions.json` обнуляются на каждом
пуше. Любой новый файл состояния добавлять туда же, через `data_path()`, а не
через `Path(__file__).parent`.

Через `DATA_DIR` идут все шесть рантайм-файлов: `state.json`, `stats.json`,
`submissions.json`, `phrase_submissions.json`, `phrases_user.txt` и
`sticker_packs.json`. Из каталога
с кодом читается только `phrases.txt` — она в git и перезаливается деплоем
намеренно.

## Особенности, о которые легко споткнуться

- **FSM в памяти** (`MemoryStorage`): «Попробуй ещё», «В предложку» и сценарии
  свой мем/предложка держат `file_id` в `state.update_data`. После рестарта бота
  все кнопки под старыми мемами перестают работать («не нашёл предыдущее фото»).
- **В предложку уходит `file_id` уже отрендеренного мема**, картинка не
  перерисовывается; текст заявки — это подпись к посту в канале, а не надпись на
  картинке. Не путать с `parse_phrase`-текстом мема.
- Хендлеры обычного фото стоят под `StateFilter(None)` — фото, присланное внутри
  сценария, обрабатывается другим хендлером. Новые «глобальные» хендлеры фото
  тоже нужно ограничивать состоянием, иначе они перехватят сценарии.
- `MEME_CAPTION` содержит юзернейм конкретного бота (`@randomem_bot`).
- Количество фраз в базе пользователю нигде не показывается — это осознанное
  решение, не «забыли добавить».
- Кнопка «Добавить фразу» и `/add` **не пишут в базу напрямую** — заявка уходит
  админу (`phrase_queue`), и только `approve_phrase` вызывает
  `phrasebank.add_phrase`. Без `ADMIN_ID` заявки копятся в файле, но одобрить их
  некому. Туда же, в очередь, автоматически падает текст каждого «своего мема»
  (`offer_custom_text_as_phrase`) — с отсевом дублей по базе и по очереди, и
  тоже только на модерацию, а не сразу в базу.
- `bot.py.save` — устаревшая копия `bot.py` (артефакт nano), случайно попавшая в
  git. Править её не нужно, при правках `bot.py` расхождение не считается багом.
- Тексты бота — намеренно строчными, без заглавных и без точек в конце. Новые
  сообщения писать в том же тоне.

## Коммиты

Коммиты в этом репозитории оформляются **без трейлера `Co-Authored-By`** и без
любых других упоминаний Claude/ИИ в сообщении — это явное требование владельца
репозитория, оно перекрывает дефолтные настройки атрибуции.
